# SpacePort 每日 Station 整理协议

> 状态：进行中
> 用途：给每日整理任务、自动化任务和后续协作者一个统一执行边界。

---

## 目标

每日任务不是为了机械清理，而是围绕两个长期目标持续推进：

1. 让 `SpacePort` 逐步变成统一可进入的网页前台
2. 让这套网页前台后续能自然升到 `3D frontstage`

因此，每日任务要同时对下面三件事负责：

- 项目长期健康
- 当前站点可读性
- 信息资产不丢失

---

## 第一原则：不要把有效信息弄没

如果某个页面为了前台更清楚而要写短，必须遵守：

1. 先确认被压缩的信息是不是仍然有效
2. 有效信息不能直接删掉，要先转存
3. 转存优先放到：
   - `stations/stations-sourcebook.md`
   - `stations/station-manifest.json`
   - 对应 station 的专门文档
4. 只有在信息重复、过时、失真或误生成时，才允许直接删

一句话：

**可以压缩前台，不能直接掏空母本。**

---

## 每日任务的理想形态

每日任务不求“大修一轮”，而求每天做一件高价值、可闭环的小步推进。

最合适的单日动作一般是下面这几类：

- 补一个站点入口页
- 把一个站点整理成统一界面骨架
- 修一组坏链
- 补一个目录 README
- 把一段长文信息下沉到 sourcebook 或 manifest
- 统一一组状态字段
- 清掉一类明显的结构债
- 给后续网页 / 3D 准备一项字段或 tracker

每日只要能稳定推进其中一项，就算有效。

---

## 每日优先级顺序

当天做什么，优先按这个顺序判断：

1. 会影响入口和理解的问题
2. 会影响信息保全的问题
3. 会影响网页化准备的数据问题
4. 会影响后续 `3D` 升维的数据问题
5. 纯修辞和措辞优化

也就是说：

- 先修路由
- 再保数据
- 再做界面整理
- 最后才是润色

---

## 推荐每日检查清单

每天开始前先看：

- [stations/README.md](../stations/README.md)
- [stations/station-manifest.json](../stations/station-manifest.json)
- [stations/stations-sourcebook.md](../stations/stations-sourcebook.md)
- [SpacePort 网页化与 3D 升维准备路线图](./spaceport-web-3d-preparation-roadmap.md)

然后快速判断：

- 哪个 `station` 目前最卡
- 哪个入口最值得补
- 哪个信息有丢失风险
- 哪个技术债现在最容易清

---

## 每日允许做的动作

- 更新 README
- 补目录 README
- 修链接
- 统一字段
- 整理 manifest
- 下沉长文到 sourcebook
- 小范围重写站点首页
- 补 tracker 字段或 tracker 视图的底稿

---

## 每日尽量避免的动作

- 一次性重写全部站点
- 没有备份就大量删减长文
- 只改措辞，不改善入口和结构
- 引入一套和现有 manifest 不兼容的新字段
- 提前做太重的 `3D` 表层，而底层字段还没统一

---

## 每日任务产出格式

每次执行后，至少要能说清楚：

- 今天处理了哪个 `station` 或哪个结构问题
- 为什么今天先做这个
- 改了什么
- 哪些信息被保留到了哪里
- 下一步最自然该接什么

如果当天有改文档，优先保证这三层至少其中两层被同步：

- 前台页
- sourcebook
- manifest

---

## 适合交给自动化的日常任务

后续自动化最适合每日做的是：

1. 读 `stations/README.md`、`station-manifest.json`、`stations-sourcebook.md` 和路线图
2. 选出一个最小但高价值的整理动作
3. 优先处理入口、结构、字段或信息保全问题
4. 如果压缩首页内容，先把信息写入 sourcebook 或 manifest
5. 完成后给出一份简短结果说明和下一步建议

---

## 当前最适合持续追的长期主题

每日任务不必平均分给所有站点，可以优先围绕下面这些长期主题滚动推进：

- `stations` 首页的网页前台化
- `station manifest` 的字段稳定化
- 核心站点页的统一骨架化
- 目录 README 和中间路由补齐
- `Digital Library / Digital Stage` 的前台化
- `Baloon Live Space` 与浏览器 / 3D 舞台准备
- `MOVA` 的观看路线结构
- `Skill Forge` 的系统面板化前台准备

---

## 一句执行原则

**每天做一件对长期前台建设有帮助的事，先保住信息，再推进结构。**
