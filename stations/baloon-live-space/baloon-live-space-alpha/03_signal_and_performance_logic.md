# Signal and Performance Logic / 信号层与表演逻辑

## 为什么信号层重要

如果实时音画只是一堆效果，它很容易变得随机、难控，也不适合表演。"信号层"是音乐、画面、空间和表演之间的中间语言。

这套语言目前最关键的词：

| 词汇 | 说明 |
|---|---|
| **Envelope** | 信号的整体包络，控制渐变与持续感 |
| **Peak** | 瞬时峰值，用于触发爆发型视觉 |
| **Band Energy** | 高 / 中 / 低频段能量，分别驱动不同视觉层 |
| **Fallback / Decay** | 回落速度，决定画面是"弹回去"还是"慢慢落" |
| **Gain** | 增益控制，校准输入灵敏度 |
| **State** | 当前系统所在的表演状态段落 |
| **Manual Override** | 手动干预，在自动响应之上保持人工控制权 |

## 这次 Alpha 实际用了什么

这次用得最多的是比较简单的版本：

- 高 / 中 / 低频能量
- 增益
- 回落
- 简单节奏强调

哪怕只是这样，也已经足够驱动色块和灯光变化、画面脉冲、舞台对象的推进和旋转、与声音联动的材质行为。

这说明：**少量但稳定、可读的信号，比复杂但不稳定的信号更有表演价值。**

## 音频检测和 Tap 的区别

实时表演有两套很重要的逻辑，两者不能互相替代：

### 音频检测 —— 持续能量

适合给系统一种持续性的能量状态：

- 画面整体呼吸
- 灯光亮度变化
- 空间推进感
- 高中低频对应的视觉分层

更像一种**连续的身体感**。

### Tap / BPM —— 精准节拍

适合结构化的精确节拍控制：

- 某个爆闪点的触发
- 某个 clip 的切入时机
- 某个分段切换
- 明确的节奏组织

更像一种**结构化的拍点控制**。

### 两者结合

> **音频检测负责持续能量，Tap / BPM 负责精准打拍子。**

这个组合会比单独依赖某一边更完整。

## State 为什么重要

单一响应很容易变平，但 state 可以把系统组织成表演结构。比如：

- `idle` → 等待 / 间奏状态
- `intro` → 进入段落
- `build` → 积累推进
- `peak` → 高潮爆发
- `outro` → 收尾

clips、特效、镜头、节拍、材质反应，在不同 state 里有不同规则。这样实时系统才不只是"在动"，而是"**在演**"。

## 离线与实时的关系

不在离线和实时之间二选一，而是两边共享一套信号思维。

这些词——`envelope`、`peak`、`band energy`、`state`、`manual override`——无论做离线影像还是实时演出，都可以共用。区别只是复杂度和控制方式不同。

**长期目标：建立一套可以在离线和实时两边迁移的视听设计语言。**
