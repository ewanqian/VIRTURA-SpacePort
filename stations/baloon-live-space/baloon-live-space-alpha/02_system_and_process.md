# System and Process / 系统与创作过程

## Core Pipeline / 核心链路

这次系统的主链路是：

```
audio input → Resolume Arena → Spout → Unity → capture card → Mac livestream
```

- 音频进入 Arena 做实时音画处理
- 通过 **Spout**（基于显卡缓存的实时视频传输协议）把画面传到 Unity
- Unity 负责空间化呈现
- 最后通过采集卡进 Mac 直播

Spout 让 Arena 和 Unity 之间可以直接交换实时画面，不需要重的中间导出过程，特别适合实时表演工作流。

## 这次具体做了什么

最基础的结构是：

- 把音乐拆成高频 / 中频 / 低频
- 每个频段分别驱动不同的色块和灯光变化
- 加入 fallback / 回落，让画面慢慢落下而不是亮一下就没
- 在此基础上加入往后推、滚动、持续转动的空间感

视频构成被组织成一种有点像黑胶、又有点像卷起来的光盘的阵列结构——围成一个圆圈，上下做成从大到小的曲线阵列。最终不是一个平面 visualizer，而是一个可进入空间的舞台对象。

## 黑胶输入

第二天早上把音频输入接到了黑胶系统。家里本来就有交响乐、人声、流行、电子等专辑，等于把原本日常听音乐的状态直接接进这套实时系统，让它成为直播和视觉驱动的一部分。

目前底噪还有待优化，但这个方向是成立的。

## 为什么优先稳定而不是 4K

这次以 720P / 1080P 为主，码率控制在 4M–10M 之间。

因为有些画面是 60 帧且像素密集，码率太低会压糊。实时表演工作站的判断是：**更轻量、更少依赖、更可靠，优先保证稳定帧率和长时间直播。**

## Arena 在这次系统里承担了什么

Arena 是这次系统里非常重要的中间层，承担了：

- 音频输入分析
- 高 / 中 / 低频分离与增益调整
- fallback / decay 控制
- 滤镜响应
- **BPM / resync / tap**

### BPM / Resync / Tap 为什么重要

这说明 Arena 不只是做"被动听声音"的响应，还可以通过节拍系统组织表演：

- 按 **BPM** 去调系统节奏
- 用 **tap** 精准打拍子
- 用 **resync** 在乱掉之后重新对齐节奏

这样不只是"音频检测给一个大概的能量"，而是可以手动、结构化地把拍点打准。

## Clips 和 State 的做法

这是后面更感兴趣的一种实时演出玩法。

把以前做过的好看视觉拆成可以搭配的 **clips**，再分成不同分段组成不同的 **state**。比如：

- 爆闪类 clips
- 节奏型 clips
- 氛围型 clips
- 过渡型 clips
- 强冲击型 clips

好处是：

- 系统更稳、可控性更强
- 可以系统化调度
- 不会过度暴露"单个实时特效"的单薄
- 巧妙结合实时音频驱动和实时特效

一个比较成熟的实时系统，不一定是全靠生成，而是：

> **可拆分 clips + state 管理 + 音频检测 + BPM / tap + 少量实时特效**

这种组合更稳，也更有表演性。

## 这套方法为什么对我重要

这套系统不只是"做一个 visualizer"，它会把我放进一种表演状态，逼着我去想：段落、节奏、结构、切换、稳定性、观众会不会继续看。

它不只是技术系统，也是在训练一种表演和组织视觉的方式。
