# Skill: Project Checkpoint

## Description
Use this skill when a project reaches a meaningful intermediate state and needs a checkpoint note.

## Use when
- a project changed state
- a new version was produced
- a task batch finished
- handoff may happen
- current progress should be preserved

## Inputs
- project name
- current folder or page
- latest changes
- unresolved items
- related file links

## Steps
1. Identify the current project state.
2. Summarize what changed.
3. Record why the change matters.
4. Note unresolved issues.
5. Add next-step directions.
6. Save the checkpoint in the appropriate folder.
7. Update entry page if the public state changed.

## Outputs
- checkpoint note
- short status summary
- next-step section
- links to relevant files

## Checklist
- Can the future self continue from here?
- Can another collaborator understand the current state?
- Are changes and next steps both recorded?
