# Patterns

## Pattern: raw to structured
Use when a long chat, transcript, or brainstorm needs to become reusable.

Steps:
1. Identify the main topic.
2. Extract 3-5 core judgments.
3. Separate summary from raw notes.
4. Add links, context, and next-step hints.
5. Place in correct folder.
6. Update entry page if discoverability matters.

## Pattern: internal to public
Use when internal dense notes need a readable public version.

Rules:
- remove unnecessary repetition
- keep the key judgment
- preserve practical meaning
- reduce private shorthand
- add an entry sentence for first-time readers

## Pattern: checkpoint preservation
Use when a project changes state.

Keep:
- current status
- what changed
- what remains unresolved
- where the next person should continue

## Pattern: library to stage
Use when a knowledge block should become visible.

Transform:
- internal notes -> readable summary
- summary -> entry page
- entry page -> linked public path
